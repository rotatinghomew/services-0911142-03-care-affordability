# 资料与统计口径

`households` 以家庭为抽样与共同资源单位，收入是每月税后可支配收入区间；上界 null 为开区间，不可用中点替代。`membership_status=disputed` 表示成员归属尚待确认。成员与费用通过 `member` 关联；`service_hours` 为实际需求记录，`purchased=false` 表示未购买，不能据此改成零需要。交通费 null 为漏报。`tariffs` 按月份生效，`hour_price` 单位为元每小时，`eligible_share` 对具资格成员服务费补助，`household_cap` 为每户当月合计上限，扣除的生活保留资源由 `disposable_deduction` 约定。研究人员可选择其他合理尺度，但须标记为情景假设。`stratum/psu/weight` 是分层整群抽样字段，不把每个成员当独立家庭。

## 原始表

- `households`：150条示例，主键为 `household`。字段：`household`, `zone`, `income_low`, `income_high`, `weight`, `stratum`, `psu`, `membership_status`。
- `members`：450条示例，主键为 `member`。字段：`member`, `household`, `role`, `needs_care`, `subsidy_eligible`。
- `bills`：900条示例，主键为 `bill`。字段：`bill`, `member`, `period`, `service_hours`, `transport`, `meal_fee`, `purchased`。
- `tariffs`：2条示例，主键为 `period`。字段：`period`, `hour_price`, `eligible_share`, `household_cap`, `disposable_deduction`。

## 家庭可负担性口径

费用浏览（`explore`）只描述挂牌服务费；家庭试算（`scenario.py`）在家庭层面按下列口径计算，任何数字不写回原始表：

1. **共同资源与家庭层面补助**。收入、生活保留额、补助封顶均以户为单位：补助先按具资格成员的服务费逐人计算，再对整户合计只扣一次并受 `household_cap` 封顶；被封顶削减的部分作为 `cap_clawback` 单独披露，便于识别是哪条收费/补助条款造成变化。
2. **净支出区间**。净支出 = 计入的服务费 + 餐费 + 交通费 − 封顶后补助。交通费漏报同时返回点值（中位数插补/按0/不计入，由情景选择）与可成立区间（下界0、上界同期同范围观测最大值），不把漏报静默当0。
3. **负担率区间与三分类**。可支配资源 = 收入区间 − 每户生活保留额。负担率下界 = 净支出下界/可支配上界，上界反向；收入开区间不产生有限的负担率端点。整个区间高于负担线为“超过”，整个区间不高于为“低于”，跨越或端点缺失为“不可判断”；可支配上界不大于0的户直接判超负担并注明原因。不使用收入档位中点，不生成精确排名。
4. **成员关系待确认**。`disputed` 家庭即使数值区间完全落在一侧，也强制归入“不可判断”并注明家庭构成可能变化。
5. **消费选择与统一服务情景**。`observed` 只计入已购买账单，`needs_care=true` 但未购买的账单计入未满足需要户数与服务费缺口，不进入支出；`uniform` 忽略购买状态，按记录小时数（或情景指定的统一小时数）把同一服务包放到每户，避免把没购买解释成没有需要。
6. **加权总体与不确定性**。所有总体比例与均值使用 `weight`；不确定性用分层整群自助法（层内对 PSU 有放回重抽，户权重随 PSU 抽中次数放大，固定种子200次），单 PSU 层不伪造区间。情景对比使用相同家庭基础与同一套重抽做配对差值区间。
7. **逐户可核对**。每户返回逐账单过程（是否计入、补助资格、交通费处理）与家庭层面汇总过程（封顶前后、净支出与负担率公式），窗口人员可点开一户完整复核。

## 版本与扩展

`fixtures/data.json` 是完整导入材料，`product.json` 是当前浏览器默认选择与试算默认参数。全量导入校验后按规范化内容指纹保存，相同内容不重复建版本。原始事实不原地修改；资料修订形成新版本，收费情景调整只存在于试算请求与存档中。`null` 表示明确未观测，不因筛选或合计自动变为0。

`care_affordability/domain.py` 保留字段校验及挂牌费用描述；`scenario.py` 承载家庭区间核算、加权推断与情景对比；`service.py` 连接范围选择、数据版本与服务端计算后的存档；`storage.py` 管理不可变数据和带 `kind` 类型的保存材料（旧存档自动按浏览记录迁移）；`web/app.js` 提供浏览、试算、对比和导出交互，前端只渲染服务端结果。保存的材料同时包含原数据与选择，打开旧材料不重算为新数据。新增分析不能丢失现有原始记录核对与历史材料读取能力。
